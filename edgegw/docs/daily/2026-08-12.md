## 三、踩坑记录（面试素材）

### 坑 1：DeviceRegistry 编译报错 —— `&(*node)[part]` 取临时对象地址

**现象**：`taking address of rvalue` 编译错误。

**根因**：`operator[]` 返回临时节点，`&` 取地址后临时对象销毁，指针悬空。

**解决**：先绑定到引用再取地址：
```cpp
const YAML::Node& child = (*node)[part];   // 引用延长生命周期
node = &child;
```

**经验**：对 `operator[]` 结果取地址必须经过引用变量。这是 C++ 临时对象生命周期的经典考点。

### 坑 2：yaml-cpp 0.6.x const operator[] 链式取值失效

**现象**：`ConfigManager::Get()` 多级键（`mqtt.host`）返回默认值，但 yaml-cpp 直接调用正常。

**根因**：yaml-cpp 0.6.x 的 **const Node::operator[]** 链式赋值会丢失子节点关联（成员变量 + 逐级 `node = node[part]`）。

**解决**：**加载时展平为 `std::map<std::string, std::string>`**（Load 时遍历，Get 查 map）——绕开库 bug，还更快。

**经验**：第三方库有 bug 时，换架构绕开比死磕 API 更高效；"加载时解析 + 运行时查 map"是企业级配置管理的标准模式。

### 坑 3：Mongoose 7.15 的 mg_http_reply 第 3 参数是 headers

**现象**：`wget` 报 `bad header line: application/jsonContent-Length: 15`。

**根因**：Mongoose 7.x 的 `mg_http_reply(c, code, headers, fmt, ...)` 第 3 参数是**完整 HTTP 头**，不是 content-type。传 `"application/json"` 被当成 header 行。

**解决**：
```cpp
mg_http_reply(c, 200, "Content-Type: application/json\r\n", "...");
```

**经验**：**用库之前先 grep 头文件确认签名**（`mg_http_reply` 签名查证）。

### 坑 4：Mongoose 7.15 WebSocket 需要显式 mg_ws_upgrade

**现象**：WS 握手后服务端无响应（TCP 通，101 不返回）。

**根因**：Mongoose 7.15 的 `mg_http_listen` 收到 WS 升级请求后，**必须显式调用 `mg_ws_upgrade(c, hm, nullptr)`**，否则连接挂着。

**解决**：`WsHandler` 里处理 `MG_EV_HTTP_MSG` 时调用 `mg_ws_upgrade`。

**经验**：Mongoose 7.15 的 WS 流程是"HTTP 升级 + 显式 upgrade"，和旧版自动升级不同。且 **`mg_ws_upgrade` 返回 void**（不是 bool），直接调用。

### 坑 5：文件名拼写错误（wedsocket vs websocket）

**现象**：`wedsocket_server.cpp` 编译正常（CMake GLOB 不报错），但文件名错误。

**解决**：重命名为 `websocket_server.cpp`。

**经验**：CMake `file(GLOB)` 不会校验文件名，拼写错误不会报错——注意文件命名。

### 坑 6：spdlog 头文件缺失 —— SPDLOG_FMT_EXTERNAL

**现象**：`fatal error: spdlog/fmt/bundled/core.h: No such file or directory`。

**根因**：Buildroot 编译 spdlog 时用**外部 fmt**（`SPDLOG_FMT_EXTERNAL`），不打包 bundled fmt；头文件仍引用 bundled。

**解决**：编译前定义宏：
```cpp
#define SPDLOG_FMT_EXTERNAL
#include "logger/logger.hpp"
```

**经验**：Buildroot 环境下 spdlog 必须配合 `SPDLOG_FMT_EXTERNAL` 使用。

### 坑 7：spdlog 链接失败 —— 缺 fmt 库

**现象**：`undefined reference to fmt::v6::internal::basic_data<void>::digits`。

**根因**：CMakeLists 没链接 `fmt`（spdlog 的依赖）。

**解决**：`target_link_libraries` 加 `fmt`。

**经验**：第三方库的"头文件 + 库"必须配套；spdlog 依赖 fmt 库。

### 坑 8：日志文件 0 字节 —— spdlog 缓冲未刷盘

**现象**：终端有日志，文件为空。

**根因**：spdlog 默认缓冲，不立即写盘。

**解决**：
```cpp
g_logger->flush_on(spdlog::level::info);   // info 及以上立即刷盘
```

**经验**：嵌入式日志必须**实时刷盘**，否则程序崩溃丢日志。

### 坑 9：git push 超时误判

**现象**：`git push` 命令超时，误以为推送成功（`git status` 显示 ahead 5）。

**根因**：GitHub 网络不稳定（国内环境），push 挂起；`git rev-list --left-right --count` 输出解读错误。

**解决**：用 `git status -sb` 明确看 `[ahead N]`，确认推送成功再继续；网络不好时换 443 端口。

**经验**：**判断推送成功的唯一标准是 `git status -sb` 显示 `[ahead 0]`** 或 GitHub 页面可见。

### 坑 10：pkill -f 误杀 mosquitto（昨天遗留补充）

**现象**：`pkill -f edgegw` 把 mosquitto 也杀了（配置文件路径含 edgegw）。

**解决**：用 `pkill -x edgegw`（精确匹配可执行名）。

**经验**：`pkill -f` 匹配完整命令行，危险；用 `-x` 或 `pidof`。

## 四、架构决策记录

### 4.1 Web/Qt 与网关通讯：为什么用 HTTP+WebSocket 而不是 MQTT

- **浏览器不支持 MQTT**（TCP 之上的自定义协议，浏览器只有 HTTP/WS）
- **协议分层**：MQTT 是设备层（ESP8266↔网关），HTTP/WS 是应用层（Web/Qt↔网关）
- **双端统一**：Web 和 Qt 共用同一套 API → 天然同步

### 4.2 JSON 库选型

| 层 | 语言 | 库 |
|---|---|---|
| ESP8266 | C | cJSON |
| RK3568 网关 | C++14 | rapidjson |
| Qt | C++/Qt | QJson |

### 4.3 日志模块设计

- **sink**：终端（带颜色）+ 文件（滚动 5MB×3）
- **级别**：debug/info/warn/error，从 yaml 配置
- **刷盘**：`flush_on(info)` 实时落盘
- **分级**：关键事件 Info，传感器明细 Debug
