## 三、踩坑记录（重点面试素材）

### 摄像头链路（12 个坑）

#### 坑 1：板子 mjpg-streamer 坏（undefined symbol）

**现象**：`mjpg_streamer: symbol lookup error: undefined symbol: parse_resolution_opt`。

**根因**：镜像里的 mjpg-streamer 换了 jacksonliam 源后编译 bug（主程序没导出插件需要的符号）。

**解决**：放弃 mjpg-streamer，改用 gstreamer（同学验证过的方案）。

#### 坑 2：execl 单参数传管道 → gst syntax error

**现象**：拍照 500，`WARNING: erroneous pipeline: syntax error`。

**根因**：`execl` 把整个管道作为一个参数传给 gst-launch，内部引号解析出错（手动多参数就正常）。

**解决**：改 `system()` 让 shell 解析参数（等价手动敲命令）。

#### 坑 3：推流进程自退

**现象**：推流 4-5 秒后进程消失。

**根因**：multifilesink 没有 `max-files=1`，无限创建新文件。

**解决**：加 `max-files=1` 强制覆盖。

#### 坑 4：抓拍半帧（"从上到下慢慢显示"）

**现象**：照片显示残缺。

**根因**：推流进程持续覆盖写 latest.jpg，HTTP 伺服读时文件正在被写，Content-Length 与实际不符。

**解决**：抓拍用独立静态文件 latest_snap.jpg + 完整帧校验（FF D9 结束标记）+ 最终改 base64 内嵌响应。

#### 坑 5：孤儿 gst 进程占设备

**现象**：`Device or resource busy`，单帧抓拍失败。

**根因**：网关被杀后 gst 子进程成孤儿继续占 /dev/video0。

**解决**：Init 时 `pkill -9 -f gst-launch-1.0` 清理 + 单帧失败回退复制。

#### 坑 6：SIGKILL 弄脏 rkisp（最严重的坑）

**现象**：停止推流后所有采集失败，gst 打开设备成功但收不到帧（无报错）。

**根因**：SIGKILL 强杀 gst，rkisp 驱动 STREAMOFF 没执行，内核流状态卡死。

**解决**：SIGINT 优雅停止（等 5 秒）+ SIGTERM 兜底 + SIGKILL 仅最后手段（带警告）。已脏的设备只能重启板子。

#### 坑 7：停止推流后 MJPEG 死连接拖慢新连接

**现象**：第二次推流卡。

**根因**：停止推流没清空 stream_clients_，死连接发送缓冲堆积。

**解决**：ClearStreamClients()，停止推流时主动断开所有客户端。

#### 坑 8：IsDeviceBusy 探测干扰设备

**现象**：反复 open/close /dev/video0 探测，留下驱动脏状态。

**根因**：探测函数本身干扰设备。

**解决**：删除探测，改"单帧失败回退复制"。

### Qt 上位机链路（8 个坑）

#### 坑 9：板子 Qt 无 websockets 模块

**现象**：`Project ERROR: Unknown module(s) in QT: websockets`。

**根因**：buildroot 没勾 QT5WEBSOCKETS。

**解决**：Qt 端用 1 秒轮询替代 WebSocket（数据 3 秒一报，延迟可接受）。

#### 坑 10：linuxfb 软渲染视频卡死 + 按钮饿死

**现象**：视频流 15fps 占满 CPU，其他按钮无响应。

**根因**：linuxfb 纯软件渲染，每帧 QPixmap 缩放 + 1280x800 全屏重绘。

**解决**：改 wayland 平台（weston + Mali-G52 GPU 加速），视频流畅、按钮正常、触摸自动。

#### 坑 11：MIPI 屏没启用（设备树）

**现象**：无 /dev/fb0，DRM 只有 HDMI connector。

**根因**：编译镜像时屏幕配置没改（topeet_screen_choose.dtsi 还是 HDMI）。

**解决**：启用 LCD_TYPE_MIPI → 重编内核（./build.sh kernel）→ 只烧 boot 分区（不用重烧 rootfs）。

#### 坑 12：触摸芯片是 ft5x06 不是 gt9xx

**现象**：`grep touch` 找不到触摸设备，以为驱动没加载。

**根因**：MIPI 7 寸屏触摸是 focaltech ft5x06（设备名 "generic ft5x06" 不含 touch 字样），内核驱动其实加载了（event2）。

**解决**：wayland 下 weston 自动关联触摸（libinput），无需手动 evdev 参数。

#### 坑 13：emoji 显示方块

**现象**：按钮图标（emoji）显示成方块。

**根因**：板子镜像无 emoji 字体。

**解决**：去除所有 emoji，纯文本按钮。

#### 坑 14：weston 旋转语法

**现象**：weston.ini `transform=90` 报 `Invalid transform "90"`，weston 崩溃。

**根因**：rockchip 定制 weston 用 `/tmp/.weston_drm.conf` 文件（`output:all:rotate270`），不是标准 weston.ini。

**解决**：官方手册方法 + 触摸自动跟随旋转 + S49rotate 自启。

#### 坑 15：视频画面方向

**现象**：weston 旋转后视频画面横躺。

**根因**：摄像头传感器物理竖装，画面本身方向不正。

**解决**：**源头修正**——gst 管道加 `videoflip method=counterclockwise`，Web/Qt 都无需各自补偿。

#### 坑 16：edgegw 忙等占 37% CPU

**现象**：Qt 突然变卡，top 显示 edgegw 37% CPU。

**根因**：主循环用 spin 忙等（volatile 循环）等信号，占满一个核。

**解决**：改 `usleep(50000)`（信号会打断休眠，退出响应依然及时）。

## 四、架构决策记录

### 4.1 视频流最终架构

```text
摄像头 → gst 常驻进程 (videoflip + mppjpegenc 硬件编码) → latest.jpg
     → 网关 multipart 流 (15fps) → Web <img> / Qt 流解析
抓拍 → 单帧 gst → base64 内嵌 JSON 响应 → 前端 data URI 直显
录像 → 独立 gst 进程 (mpph264enc) → mp4
```

**三个关键决策**：
1. `system()` 启动 gst（shell 解析参数，解决 execl 引号坑）
2. base64 内嵌抓拍（绕开文件伺服的所有半帧/Content-Length 坑）
3. 源头 videoflip 旋转（一次修正，双端受益）

### 4.2 Qt 显示方案：wayland 而非 linuxfb

```text
linuxfb: 软渲染 → 视频卡 + 按钮饿死 + 触摸难配 (弃用)
wayland: Mali-G52 GPU 加速 → 视频流畅 + weston 自动触摸 + fontconfig 字体
```

### 4.3 外设闭环：乐观更新

```text
前端命令 → 网关: ①MQTT下发 ②解析命令更新状态表 ③WS推送
→ 前端控件立即同步 (不等硬件回执)
→ 组员加 ACK/状态上报后, 覆盖为真实值 (平滑升级)
```

### 4.4 屏幕方向修正分层

```text
设备树: LCD_TYPE_MIPI 启用 (显示驱动)
weston: .weston_drm.conf rotate270 (合成器旋转+触摸跟随)
gst:   videoflip counterclockwise (画面源头旋转)
```

