## 二、核心 Bug 修复：videoflip 漏加在主流管道

**现象**：新版 edgegw 部署后，gst 管道里没有 videoflip，视频画面仍横躺。

**根因**：昨天给推流管道加 videoflip 时，只加在了**重试管道**（pipeline_retry，首次推流失败才走），**主流管道漏加了**。

```cpp
// ❌ 主流管道 (Start() 首次推流) - 漏加 videoflip
" ! mppjpegenc ! multifilesink location=" + FramePath() + ...

// ✅ 重试管道 (首次失败才走) - 有 videoflip
" ! videoflip method=counterclockwise ! mppjpegenc ! multifilesink ..."
```

**结果**：首次推流成功 → 走主流管道 → 无 videoflip。只有首次失败重试才会旋转。

**修复**：主流管道补加 `" ! videoflip method=counterclockwise"`（与重试管道一致），重新编译部署。

**验证**：
- 抓帧尺寸 640x480 → 480x640（旋转 90° 生效）
- look_at 分析：画面正立，无横躺

## 三、踩坑记录

### 坑 1：8080 冲突真凶 = S99 自启的旧版 edgegw

**现象**：新 edgegw 启动报 `bind: 98`（EADDRINUSE），8080 被占。

**真凶**：开机自启脚本 `S99edgegw` 拉起的**旧版 edgegw**（pid 683，09:33 开机时自动启动）。昨天 `pkill -x edgegw` 没杀掉是因为当时根本没查清进程，今天 `ps -ef` 直接看到 pid 683。

**解决**：`pkill -9 -f edgegw`（注意会误杀 mosquitto，因为 edgegw.conf 匹配）→ 重启 mosquitto → 启动新版。

**教训**：板子重启后 S99 会自动拉起旧版，部署新版前必须先杀旧进程，否则 scp 会 Text file busy。

### 坑 2：WSL ssh 连板子 banner 超时（误判一上午）

**现象**：`Connection timed out during banner exchange`，TCP 22 通但收不到 SSH banner。

**真相**：**dropbear 响应慢**（超过 6 秒才回 banner），不是连不上。我之前 ConnectTimeout 设 6-8 秒太短，误判成"板子 sshd 挂了"，绕了一大圈（试 adb/telnet/expect 免密）。

**解决**：ConnectTimeout 设 25 秒就通。Windows ssh 和 WSL ssh 都能连。

**教训**：banner 超时不等于连不上，先加大超时重试再下结论。

### 坑 3：板子没有 curl

**现象**：`-sh: curl: not found`，无法在板子上用 curl 调 API。

**解决**：从 WSL 用 curl 操作板子 HTTP API（WSL 网络到板子 8080 是通的，只是 22 慢）。打通了"agent → WSL curl → 板子 API"的全自动通道，后续无需用户在板子上手敲 API 命令。

### 坑 4：PowerShell 转义地狱（工具层面）

**现象**：`|`、`$(nproc)`、`%{...}` 等被 Windows PowerShell 抢先解析。

**解决**：整条 bash 命令用**单引号**包裹传给 `wsl bash -c`；expect 脚本写文件避免引号嵌套。

## 四、部署流水线（今天跑通的）

```text
WSL 编译 (cmake --build build/arm64 -j 8)
  → expect 自动 scp (rscp.sh, 密码 topeet)
  → 板子启动 ./edgegw development.yaml
  → WSL curl POST /api/camera/start 启动推流
  → curl GET /api/camera/status 查状态
  → curl GET /api/camera/last_photo 抓帧验证方向
```

**关键 API**：
```text
POST /api/camera/start         启动推流
POST /api/camera/stop          停止
POST /api/camera/snapshot      抓拍
POST /api/camera/record/start|stop  录像
GET  /api/camera/status        状态 (streaming/frame_ready)
GET  /api/camera/last_photo    最新帧 JPEG
```
